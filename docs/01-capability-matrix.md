## Capability matrix — Andoff / competitor feature → iOS verdict

Legend: **FULL** = clean parity · **DEGRADED** = achievable but materially weaker · **BLOCKED** = impossible for a third-party App Store app · **EU-ONLY** = gated to EU devices/accounts

### Andoff's own feature set

| Andoff feature | iOS verdict | How (or why not) |
|---|---|---|
| Per-app three-state status (Default / Blocked / Protected) | **DEGRADED** | `ManagedSettingsStore().shield.applications: Set<ApplicationToken>?`. "Blocked" becomes *launch-then-cover-with-shield*, not launch prevention. "Protected" has no per-app form — only device-wide `store.application.denyAppRemoval`. You never see which app it is: tokens are opaque. |
| Blocked app also stops **background execution** | **BLOCKED** | Android `setPackagesSuspended` suspends the process. iOS shields are a UI cover drawn over a *running* app. Shielded apps keep background modes (audio, VoIP, location, BGTaskScheduler) and keep receiving pushes. No third-party API can suspend, freeze, force-quit, or deny background execution to another process. |
| Blocking **system apps** (stock browser, Play Store, Settings) | **BLOCKED (mostly)** | `FamilyActivityPicker` vends a system-curated list; Apple first-party apps are largely absent. **Settings.app cannot be shielded at all** — which structurally guarantees the revocation escape hatch stays open. (A search-synthesis claim that Jomo "shields Settings during strict sessions" has no API basis — *(unverified)*, and I am calling it false.) Safari is handled by a different surface entirely (`shield.webDomains`, `webContent`). |
| Installation Protection — **Solid** (no installs at all) | **FULL** | `store.application.denyAppInstallation = true`, plus `store.appStore` (`denyInAppPurchases`, `maximumRating`, `requirePasswordForPurchases`). |
| Installation Protection — **Smart** (auto-suspend new installs) | **BLOCKED** | No `PACKAGE_ADDED` analogue. iOS gives third parties no install-event callback and `FamilyActivitySelection` is a static user-made token set that never auto-expands. Degraded substitute: force Solid mode, so nothing new can appear. |
| **Locking mechanism**: password or time delay | **FULL** | Pure application logic. Persist the pending change + earliest-apply timestamp; gate every `ManagedSettingsStore` mutation behind it. Store the deadline in Keychain with `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly` so delete-and-reinstall does not reset the clock. |
| **"Permit tightening changes directly"** (ratchet) | **FULL** | Pure application logic. Classify every mutation as *tighten* (apply synchronously) or *loosen* (queue behind the lock). Zero platform privilege required. **This is the flagship port.** |
| **Auto-Revert** (temporary loosening that self-reverts) | **FULL** | Write the revert deadline to the App Group; re-tighten on next app foreground; arm a `DeviceActivitySchedule` + `UNCalendarNotificationTrigger` as backstops. Caveat: a schedule cannot be shorter than 15 minutes, so sub-15-minute reverts must be foreground/notification-driven. |
| **Uninstall protection on Andoff itself** (revoke behind the lock) | **BLOCKED** | Apple documents the opposite behavior for `.individual`: authorization *removes* the anti-bypass restrictions. `denyAppRemoval` is device-wide, is only honored under `.child`, and is reported to get stuck on after your app is uninstalled (thread 818905). |
| Block **Safe Mode** / disable power button | **BLOCKED** | iOS has no safe mode and no third-party control over hardware buttons, DFU, or recovery mode. |
| Block **Factory Reset** | **BLOCKED** | No influence over Erase All Content and Settings. Requires MDM supervision. |
| Disallow **Developer Options / USB debugging** | **BLOCKED** | No equivalent user-facing setting to lock, and no API. |
| Block **Android WebView** (kill web rendering everywhere) | **BLOCKED** | `WKWebView` is a framework linked into each app's process, not a separately installed suspendable package. There is nothing to block. |
| Protect a **specific third-party filter/DNS/VPN app** from removal or force-stop | **BLOCKED** | Cannot enumerate installed apps, cannot protect a named third-party app, cannot force a DNS/VPN profile to stay enabled. `NEDNSSettingsManager` configs are user-disableable in Settings. |
| Push **enterprise policy into another app** (Edge URLBlocklist) | **BLOCKED** | Requires MDM. Degraded substitute: Safari-side only via `shield.webDomains` / `webContent.blockedByFilter`, plus shielding other browsers that the picker exposes. |
| **Advanced Mode** progressive disclosure | **FULL** | Pure UI. Worth copying — lets you ship a simple default surface while exposing MDM-grade knobs. |
| System-drawn suspension dialog (customizable icon/title/message/button) | **DEGRADED** | `ShieldConfiguration` (ManagedSettingsUI) — blur style, background color, one `UIImage` icon, two `Label`s, two button labels, one primary-button background color, and on iOS 26.4+ up to three `secondaryButtonSubmenuItems`. **No custom views, no SwiftUI, no animation, no text input, no live countdown.** There is no secondary-button background color. |
| Time-of-day / weekday scheduling | **FULL (a feature *addition* over Andoff)** | `DeviceActivitySchedule(intervalStart:intervalEnd:repeats:warningTime:)`. Andoff has no scheduling surface at all. |

### Competitor mechanics worth stealing

| Mechanic (source) | iOS verdict | How |
|---|---|---|
| Shield → open **your** app for a full-screen intervention | **FULL on iOS 26.5+ only** | `ShieldActionResponse.openParentalControlsApp`. Below 26.5 there is **no supported mechanism** — Apple Frameworks Engineer: "Some apps may have figured out ways to call up private API that should be rejected in App Review." Fallback: a `UNUserNotification` the user must tap (~1s+ delay, suppressible by Focus), or a user-built Shortcuts personal automation (what ScreenZen and one sec do). |
| Shield submenu: "1 more minute / 15 more / 1 hour" (Apple's own example copy) | **FULL on iOS 26.4+** | `ShieldConfiguration.secondaryButtonSubmenuItems` (max 3) + `ShieldAction.firstSecondarySubmenuItemPressed` / `.second…` / `.third…`. System auto-adds Cancel. |
| Breathing animation / typed intention / math problem (one sec, ScreenZen, Jomo, Clearspace) | **FULL** — *but only inside your own app* | Cannot run in the shield. Requires the 26.5 handoff, or a Shortcuts automation on older OS. |
| **NFC tag** to start/end a session (Brick, Unpluq, Jomo, Blok, Monk, Foqos) | **FULL** | Core NFC. Background NDEF tag reading needs a universal link and iPhone XS+ with screen on; a **foreground tap inside your app is the reliable path**. |
| Camera-verified pushups/squats to unlock (Clearspace) | **FULL** | Vision body-pose + CoreMotion, in your app. Independent of Screen Time APIs. |
| "Monk Mode" / Deep Focus — cannot be ended early (Roots, Opal) | **FULL as friction, DEGRADED as enforcement** | Your app simply refuses to lift the shield. But the user can still revoke in Settings in four taps. |
| Undeletable-during-session (Opal, AppBlock, Monk Strict Mode) | **DEGRADED / effectively BLOCKED under `.individual`** | `store.application.denyAppRemoval = true` is device-wide and, per Apple staff (thread 729637), only honored when authorized via `.child`. Under `.individual` it is not a guarantee. |
| Accountability partner approves unlocks (ScreenZen) | **DEGRADED** | You can build it (your own backend + push). But you cannot detect revocation promptly — `$authorizationStatus` does not reliably emit on revoke while backgrounded (thread 820796, no Apple response). Use a **server-side heartbeat**: client posts "still authorized" on every foreground/BGAppRefresh; the *server* infers tampering from missing beats. |
| **Pickup-count limits** ("block after N daily opens") | **BLOCKED as enforcement, DEGRADED as display** | `DeviceActivityData.ApplicationActivity.numberOfPickups: Int` exists but is readable **only** inside the sandboxed report extension and cannot be exported. Products that enforce pickup limits are counting their *own* shield events. You can do the same via `ShieldActionDelegate` writes. |
| Daily screen-time budget / "block after N minutes" | **DEGRADED — do not put on the critical path** | `DeviceActivityEvent(…threshold: DateComponents)` + `eventDidReachThreshold`. Broken across iOS 26.2–26.5.2 (fires immediately / at 0 minutes / twice / never). Must be idempotent and independently verified against your own timestamps. |
| Usage charts, streaks computed from real usage, partner-visible stats, export | **BLOCKED (non-EU)** | Report extension sandbox is absolute (Apple DTS confirmed). App Group UserDefaults writes silently dropped; file writes fail; HTTP blocked; local notifications blocked; `UIPasteboard` fails; iCloud KVS `synchronize()` returns false. You may only *render* a `DeviceActivityReport` SwiftUI view inside your app. |
| Real app names + icons for blocked apps | **BLOCKED (non-EU) / EU-ONLY** | `Application(token:).bundleIdentifier` and `.localizedDisplayName` return `nil` under `.approved`. De-tokenization requires `AuthorizationStatus.approvedWithDataAccess` + `com.apple.developer.family-controls.app-and-website-usage` (iOS 26.4+), **EU devices with EU Apple Accounts only**, one app per device. Non-EU workaround: Apple's own `Label(token)` display views. Note: `ShieldConfigurationDataSource` *does* receive real display names and bundle IDs — but cannot export them. |
| Block `youtube.com/shorts` but allow `youtube.com` | **BLOCKED** | `WebDomainToken` is whole-domain only. No per-URL or per-path blocking. |
| System-wide website blocking across all browsers (Freedom) | **DEGRADED + high risk** | Requires `NEVPNManager`/`NEFilterDataProvider`. Guideline 5.4 requires **organization** enrollment (not individual) and "approved provider" status; non-compliance carries App Store *and* Developer Program removal. Only one VPN active at a time, so it conflicts with the user's real VPN. Not recommended for v1–v3. |
| Continuous screen recording + AI nudity detection (LivingRoom) | **DEGRADED + heavy** | ReplayKit `RPSystemBroadcastPickerView` + Broadcast Upload Extension (~50 MB budget) + SensitiveContentAnalysis (`com.apple.developer.sensitivecontentanalysis.client`). HDCP blocks Netflix/Disney+ (black screen). *(framework attribution inferred from behavior, not vendor-stated — unverified)* |
| Detect that another app was just opened | **BLOCKED** | Apple DTS (thread 838231): no supported API. Not app-open callbacks, `NSUserActivity`, Shortcuts intents, URL schemes, App Intents, or Live Activities. |
| Bring your own app to the foreground programmatically | **BLOCKED** | Apple DTS: "iOS does not provide a supported API for an application to programmatically bring itself to the foreground, and Family Controls does not grant any exceptions for this purpose." Only `.openParentalControlsApp` (26.5+). |
| Open the **blocked** app after a successful intervention | **BLOCKED** | You hold only an opaque `ApplicationToken`. `OpenAppFromApplicationTokenIntent` was requested (FB15500695) with no Apple response. **The user must navigate back themselves — design your copy around this.** |
| Draw a custom full-screen overlay over another app | **BLOCKED** | No `SYSTEM_ALERT_WINDOW` / `TYPE_APPLICATION_OVERLAY` analogue; no window level above the frontmost app. |
| macOS companion (Opal, Freedom, ScreenZen ship one) | **BLOCKED** | Apple Frameworks Engineer (thread 717569): "The Screen Time APIs are currently for iOS only." Mac Catalyst fails at runtime: `The connection to service named com.apple.FamilyControlsAgent was invalidated: failed at lookup with error 159 - Sandbox restriction.` **Target iOS + iPadOS only.** visionOS is contradictory in Apple's own docs and authorization always fails for an iPhone/iPad app running there. |
